# Qmini — 极低内存语音开黑软件 设计文档

**日期**: 2026-05-08
**状态**: 设计稿

---

## 1. 概述

Qmini 是一款面向 5-10 人游戏开黑场景的语音聊天软件，核心追求是**极低内存占用（目标 6-8MB）**和**极低性能开销**。仅支持 Windows 平台，驻留系统托盘，通过全局快捷键操作。

---

## 2. 架构

### 2.1 总体架构

单体式进程，内部多线程协作：

```
┌──────────────────────────────────────────────────┐
│  Qmini.exe                                       │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐  │
│  │ 音频采集  │→ │ Opus编码 │→ │ UDP 发送       │  │
│  │ WASAPI   │  │ 16kbps   │  │ (P2P / TURN)   │  │
│  └──────────┘  └──────────┘  └───────┬────────┘  │
│                                      │           │
│  ┌──────────┐  ┌──────────┐  ┌───────▼────────┐  │
│  │ 音频播放  │← │ 解码混音 │← │ UDP 接收       │  │
│  │ WASAPI   │  │ Opus解码  │  │ + 抖动缓冲     │  │
│  └──────────┘  └──────────┘  └────────────────┘  │
│                                                  │
│  ┌──────────────────────────────────────────────┐ │
│  │ 信令客户端 (HTTP/WebSocket)                  │ │
│  └──────────────────────────────────────────────┘ │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐  │
│  │ 托盘图标  │  │ 全局快捷键│  │ 配置管理       │  │
│  └──────────┘  └──────────┘  └────────────────┘  │
└──────────────────────────────────────────────────┘
```

### 2.2 模块划分

| 模块 | 文件 | 职责 |
|------|------|------|
| 音频采集 | `audio_capture.c` | WASAPI 捕获，16kHz 16-bit 单声道 |
| 音频播放 | `audio_playback.c` | WASAPI 渲染，多路混音输出 |
| Opus 编解码 | `codec.c` | Opus 编码/解码封装 |
| 抖动缓冲 | `jitter_buffer.c` | 抗网络抖动的自适应缓冲区 |
| 网络传输 | `network.c` | UDP P2P 连接管理，TURN 回退 |
| 信令 | `signaling.c` | 信令协议，房间/成员管理 |
| 系统托盘 | `tray.c` | 托盘图标 + 右键菜单 |
| 快捷键 | `hotkey.c` | 全局快捷键注册（PTT / 静音切换） |
| 配置 | `config.c` | INI 配置文件读写 |
| 环形缓冲 | `ringbuf.h` | 无锁 SPSC 环形缓冲区 (header-only) |
| 入口 | `main.c` | 初始化、消息循环、模块协调 |

## 3. 音频管道

### 3.1 参数

| 参数 | 值 |
|------|-----|
| 采样率 | 16 kHz |
| 声道 | 单声道 (Mono) |
| 位深 | 16-bit PCM |
| 帧长 | 20 ms（每帧 320 字节 PCM） |
| Opus 码率 | 16-24 kbps |
| 编码后每帧 | ~40-60 字节 |

### 3.2 采集

- 使用 WASAPI Capture，事件驱动模式
- 采集线程推入 SPSC 环形缓冲区，编码线程取出
- 静音时采集线程休眠，不消耗 CPU

### 3.3 编解码

- Opus 库静态链接，运行时 ~200KB 代码段
- 每个远端用户分配一个独立解码器状态
- 编码器全局一个（本地只编码一路）

### 3.4 抖动缓冲区

- 每个远端用户一个独立 jitter buffer
- 容量：120 帧（2.4 秒），预分配
- 过期帧直接丢弃
- 内置 PLC（丢包隐藏）平滑处理丢包

### 3.5 混音

- 线性叠加 + 饱和截断
- 不做独立音量增益（最小化复杂度）

## 4. 网络模块

### 4.1 信令

- 信令服务器：轻量 HTTP/WebSocket 服务（C 实现，IOCP 单线程）
- 功能：注册、房间管理、ICE 候选交换
- 协议：自定义 JSON 信令，极简字段

### 4.2 P2P 连接

- ICE 协议（精简实现）：STUN 打洞 + TURN 回退
- 每路连接：5 秒心跳 NAT 保活
- 最大 9 条对端连接（10 人房间）

### 4.3 传输

- 语音数据通过 UDP 传输
- FEC 前向纠错（可选，可配置丢包率阈值触发）
- TURN 中继：UDP 中继模式，coturn 或自研精简中继

### 4.4 信令流程

```
1. 启动 → UDP 绑定本地端口 → 信令服务器注册
2. 加入房间 → 获取房间成员列表
3. 与每个成员进行 ICE 协商
4. P2P 建立成功 → 语音直连
5. P2P 失败（全部候选失败） → 切换 TURN 中继
6. 成员离开 → 自动断开对应连接，释放资源
```

## 5. 用户交互

### 5.1 系统托盘

- 托盘图标：16x16 GDI 绘制或内嵌 .ico 资源
- 右键菜单：
  - 加入房间 → 输入房间码
  - 离开房间
  - 静音切换 ✓
  - 退出

### 5.2 全局快捷键

| 功能 | 默认键 | 说明 |
|------|--------|------|
| 按键说话 (PTT) | 鼠标侧键 / 可配置 | 按住期间采集发送 |
| 静音切换 | Ctrl+F12 / 可配置 | 切换麦克风开关状态 |

## 6. 内存预算

| 项目 | 大小 |
|------|------|
| 本地音频缓冲区 | ~100 KB |
| 远端解码器 × 9 | ~1.5 MB |
| 抖动缓冲区 × 9 | ~800 KB |
| Opus 库代码段 | ~200 KB |
| 网络缓冲区 | ~200 KB |
| 配置/其他 | ~200 KB |
| 堆栈 + 程序代码 | ~3-4 MB |
| **总计** | **~6-8 MB** |

## 7. 构建环境

- 编译器：MSVC (Visual Studio) 或 MinGW-GCC
- 依赖：
  - Windows SDK（WASAPI、Win32 API）
  - libopus（静态链接）
  - 标准 C 库
- 无其他第三方依赖
